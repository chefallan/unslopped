# Rename package to unslopped

Cycle: 20260901-8c66a4

## Goal
The product is renamed from awesome-delivery-engine to unslopped across source, tests, docs and instruction files: npm name and binary `unslopped`, config `unslopped.config.json`, state dir `.unslopped/`, env prefix `UNSLOPPED_`, prose brand "Unslopped". Existing installs keep working through the upgrade: legacy instruction-file markers are replaced instead of duplicated, legacy hooks are recognized and swapped, and the legacy command names stay blocked for assistants.

## Approach
Chosen: apply the scripted sweep validated on a clone (49 files, ordered replacement rules including the escaped-boundary rule for regex literals, bin rename), then add legacy compatibility by hand with red-before-green: init block replacement accepts the old markers, install hook detection accepts the old command, the tool hook keeps blocking the old command names and the old config filename. The repo-level config file, state dir and .gitignore keep their old names during this cycle because the old installed binary runs the gates; they move in a follow-up chore after completion.
Rejected: renaming state and config inside the cycle, because the binary governing the gates would stop finding its own state mid-cycle. Rejected: a compatibility-free sweep, because both live installs (this machine, goshen-learn) would end up with duplicated instruction blocks and orphaned hooks.

## Out of scope
- Renaming `.ade/`, `ade.config.json` and .gitignore entries in this repo (post-cycle chore)
- Config or state fallback loading for old names inside the new binary (migration is a documented manual step)
- npm publish and the GitHub repository rename
- goshen-learn migration (runbook goes to the human)
