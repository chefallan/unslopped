# Add resume command and reset with goal

Cycle: 20260831-08ed52
Started: 2026-08-31T01:18:27.379Z

## Goal
Close the two UX gaps the first real ade runs surfaced: assistants and humans returning to an active cycle need one command that says where the cycle stands and what to do next, and humans abandoning a cycle need one command instead of reset followed by start. Two smaller fixes ride along: start warns when uncommitted files predate the cycle (they poison every diff-based gate), and the style scan stops flagging ade.config.json for the dash characters its own forbidden list must contain.

## Approach
Chosen: a read-only `ade resume` (alias `continue`) that reuses statusLines and adds failing checks from the last gate run plus a per-phase numbered "do next" list, and an optional goal argument on `ade reset` that delegates to cmdStart after archiving. Reset keeps its name so the existing human-only hook rule covers the new form with no new machinery.
Rejected: `ade start --fresh` with an auto-reset, because start is assistant-runnable and that flag would hand assistants an escape hatch from failing gates. Rejected: merging resume and reset into one command, because continue and abandon are opposite actions and a single name invites the wrong one.
The dirty-baseline warning lives in cmdStart before the cycle is created; the style fix is a skip of ade.config.json inside scanStyle so both the code and release gates inherit it.

## Out of scope
- `--keep-plan` carry-over of the old plan into the new cycle; plans stay in .ade/plans and can be copied by hand
- Refusing to start on a dirty tree; this cycle only warns
- CHANGELOG.md creation; logged as debt
- Regenerating instruction files for assistants not yet initialized in this repo
