# Adapt the ponytail leanness ladder so the plan names the rung it used before any code is written

Cycle: 20260909-b4c7cd
Started: 2026-09-09T23:17:43.627Z

## Goal
Adapt the ponytail leanness ladder into the plan phase. The assistant has to name the rung it climbed
to before it writes code, and the plan gate refuses a plan that names none. Source:
github.com/DietrichGebert/ponytail.

## Approach
Rung 2. The ladder check is the same shape as planSectionsCheck and criteriaVagueCheck, which already
read one section of the plan and fail with instructions. Reuse that shape, add no subsystem.

The seven rungs go into protocol.ts, which generates AGENTS.md and CLAUDE.md, so every assistant reads
the ladder before planning. The check is a regex for a rung marker over the "## Approach" section.

Chosen: a rung marker in the Approach, checked at the plan gate.

- Plan gate, not code gate. The ladder runs before code exists. Ponytail is explicit that it runs after
  the assistant understands the problem and before it picks a solution. The plan phase is that moment.
- An explicit marker, not inferred intent. A gate exits 0 or fails. Reading an Approach section and
  judging whether it was lazy enough needs a model, and no gate calls one. Writing "Rung 2" is a claim
  the human can check against the diff, which is the same contract as an acceptance criterion.
- Default on. Every other plan quality check here defaults on, and a tool built to stop slop should not
  ship its leanness rule switched off. Costs one line per plan, and the failure prints the rungs.

Rejected:
- The lite, full, ultra and off modes. Rung 1: does this need to exist. Modes are an intensity dial for a
  prompt, and these gates are mechanical, so intensity has nothing to scale. One boolean.
- A bloat scanner over the diff now, ponytail's review and audit commands. Real value, own cycle. Adding
  it here would pass the diff limit and bury the rule it enforces.
- Scoring the rung, for example refusing rung 7 when rung 2 was available. That needs to know the whole
  codebase's capabilities, which is the assistant's job, not a regex's.

Revisable: the default, and whether the marker also belongs in the commit message.

## Handoff
What to verify: an assistant cannot start coding without saying how lazy it was allowed to be.

How to reach it:
1. Start a cycle in any project on 0.1.5.
2. Fill the plan but write the approach without a rung, then run `unslopped next`.
3. The plan gate fails with `FAIL leanness ladder` and prints the seven rungs.
4. Add "Rung 2" plus a sentence to `## Approach`, run `unslopped next` again. It passes and names the rung.

Rejections to try, with what should happen:
- "Rung 0", "Rung 8" or "Rung 12": still fails. Only 1 to 7 count.
- A rung marker in `## Goal` or `## Out of scope` instead of `## Approach`: still fails.
- `practices.ladder` set to false: the check disappears from the gate.

Gotchas:
- The check reads a marker, not intent. It cannot tell whether rung 7 was honest when rung 2 was there;
  that is what the human reads the approach for. The claim is checkable against the diff, which is the
  same contract as an acceptance criterion.
- Upgrading an existing project fails its next plan gate until the approach names a rung. Called out in
  the changelog under Changed.

## Monitor
No gate failed on its first run this cycle, which is the first time that has happened. The lessons from
the previous cycle carried: reasons in parentheses under "## Files to touch", a bare "None" under
"## Open questions", one approved commit per artifact.

- Adding a default-on plan check broke twelve existing tests at once. That is what PRACTICES_OFF is for,
  and it now lists ladder alongside every other practice that defaults on. One test, the end to end cycle
  in test/cli.test.ts, runs on real defaults, so its plan fixture had to name a rung. That test is the
  only place the shipped default gets exercised, which makes it the one to check whenever a default moves.
- Writing regex and escape sequences through a python heredoc corrupted three files. `\b` arrived as a
  literal backspace byte, `\n` as a real newline. The typecheck caught two, and the third only showed
  as two passing tests failing. Escapes go through the editing tool, not through a shell heredoc. This
  cost four rounds and is the single biggest time sink of the cycle.
- prTitle picked chore again, for the same reason as last cycle: the plan commit outvoted the feature
  commit. Already logged as debt, and it happened on the very next cycle, so it is worth doing.

For next time: never put a regex or an escape sequence in a heredoc, and expect a default-on check to
need the shared test fixture updated in the same commit.
