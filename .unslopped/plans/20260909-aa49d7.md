# Add a pr quiz gate that asks the approving human comprehension questions generated from the diff

Cycle: 20260909-aa49d7
Started: 2026-09-09T21:41:59.593Z

## Goal
A pull request gate that checks the human who approves the change can answer questions about it.
The agent writes the questions from the diff, the human answers, and the deploy gate stays shut until the
answers are right. Modelled on dkamm/pr-quiz. Off by default.

## Approach
The quiz reuses the review artifact pattern in `cmdReview` (src/cli.ts:381) rather than inventing a
second mechanism. The agent writes a markdown quiz to a file, `unslopped quiz --file=<path>` parses and
stores it, and the human answers with `unslopped quiz --answer=<letters>`. Grading compares the letters to
a key held in state, never printed with the questions.

Chosen: the human answers, and the gate sits in the deploy phase.

- Human seat, not agent closed-book. The agent wrote the diff. Grading it on its own work with the diff in
  context measures nothing. This is the pr-quiz design and the reason it exists.
- Deploy gate, not release. Release asks whether the code is correct. Deploy is where a person accepts the
  change, next to `approve deploy`. A comprehension check belongs with the acceptance, not the correctness.
- Artifact plus grade command, not an interactive prompt. Every other human decision here is a command whose
  permission dialog carries the evidence. An interactive quiz would need a TTY the gates do not have.
- Multiple choice with a stored key. Grading has to be mechanical, like every other gate. Free text would
  need a model call inside the gate, which no gate does.

Rejected:
- A ninth phase between release and deploy. Costs a Phase enum change, a tracker transition and eight
  describeGate branches, for a check that already has a home.
- Free text answers graded by a model. Puts a nondeterministic call inside a gate that must exit 0 or fail.
- Quizzing on every pull request. A one-line fix does not need a quiz, so `minLines` skips small diffs, as
  pr-quiz does with its 100-line threshold.

Revisable: the pass mark, the attempt cap and the `minLines` default. No time limit, unlike pr-quiz. A wall
clock in a CLI punishes the reader who is being careful, which is the behaviour the gate wants.

## Out of scope
- Generating the questions. The agent or a configured `quizCommand` writes them, the same split as
  `reviewCommand`. No model call goes inside unslopped.
- Editing unslopped.config.json. A config change mid-cycle blocks the cycle on a human approval, and the
  feature defaults to off, so this project needs no config edit to keep working.
- Protocol and doc updates in AGENTS.md and CLAUDE.md. The gate is off by default, so no assistant
  instruction is wrong without them. Logged as debt for the next cycle.
- Posting the quiz or its result to the tracker or the pull request.

## Handoff
What to verify: the deploy gate refuses to open for someone who has not read the diff.

How to reach it, in a scratch repo or this one:
1. Set `practices.quiz` to `{ "enabled": true, "minLines": 1, "pass": 100, "maxAttempts": 3 }`. A config
   change mid-cycle needs `unslopped approve config`, so set it before starting a cycle.
2. Run a cycle to the deploy phase. `unslopped check` reports `FAIL quiz` and asks for a quiz.
3. Write three questions about the diff into quiz.md, in this shape:
   `1. Why does X happen?`, then `- a) text`, `- b) text`, then `answer: b`.
4. Run `unslopped quiz --file=quiz.md`. It prints the questions with no answer key and deletes quiz.md.
5. Run `unslopped quiz --answer=<letters>`.

Rejections to try, with what should happen:
- Wrong letters: exit 1, the missed question numbers named, the attempts left counted down.
- A fourth attempt after three wrong ones: exit 2, no attempts left, told to write a new quiz.
- An artifact with no `answer:` line, or with one option, or keyed to a letter that has no option: exit 2,
  the bad question number named.
- A new commit after passing: the deploy gate fails again, saying the code changed after the quiz.

Gotchas:
- The answer key lives in .unslopped/state.json. A determined human can read it, the same way they could
  edit any gate's state. The gate makes skipping the diff a deliberate act, not the default. It is not a
  defence against someone who wants to cheat their own review.
- The quiz counts the whole cycle diff, not a pull request diff, so `minLines` compares against
  `diffLines` since the cycle's start commit.
