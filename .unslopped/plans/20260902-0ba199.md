## Goal
All seven logged deviations are gone: the tool hook stops matching command names and the config filename inside file content, scopeCheck tolerates parenthetical notes, a config upgrade no longer reads as tampering and drift shows the changed lines, CHANGELOG.md exists and is enforced, the start refusal points at resume before reset, and every approve says what happens next.

## Approach
Chosen: make the hook read commands the way a shell does. Heredoc bodies are cut before any rule runs, the human-only and commit rules match only at command position (start of a line or after a pipe, semicolon or ampersand), and the config-file rule fires only when the filename is the target of a redirect or the argument of a writer. Drift stores the raw config text on the cycle at start and compares text, so merged defaults added by an upgrade change nothing, and the failure prints the changed lines instead of two hashes. scopeCheck strips a trailing parenthetical from declared entries. The refusal and approval messages state the next action. CHANGELOG.md starts at 0.1.0 and the existing changelog practice enforces it from now on.
Rejected: parsing shell properly, because a real parser for four rules is more surface than the rules; position anchoring plus heredoc stripping removes every observed false positive while keeping real invocations blocked. Rejected: hashing the raw text instead of storing it, because storing it is what makes the drift diff printable.
