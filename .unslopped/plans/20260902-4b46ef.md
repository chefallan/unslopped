# Show the evidence when an approval is needed

Cycle: 20260902-4b46ef

## Goal
No approval request arrives naked. When a deploy waits on a human, the tool itself prints what was verified, what approving unlocks, and how to decline, in the gate output, in resume, and echoed back by the approval. The protocol requires assistants to relay that block verbatim on every platform.

## Approach
Chosen: a briefLines function in a new src/brief.ts that reads everything from the cycle record and the repo: criteria ticked versus total from the plan, red-run and review records, diff size and file count since cycle start, commit subjects, gate runs with which phases failed and were fixed, then the unlock section from the configured commands. The deploy gate appends it to the failing approval check, resume shows it at the deploy phase, and approve deploy echoes it as the record of what was signed. One rule joins the protocol: relay the context block verbatim, never ask with a bare command.
Rejected: separate brief text per surface, because three phrasings of the same evidence will drift; one function feeds all three. Rejected: bundling the config-diff rework here, because it changes what the cycle stores and belongs to the logged debt sweep.

## Out of scope
