# Make PR review comments plain and short

Cycle: 20260901-9e69e9

## Goal
Everything unslopped posts on a pull request reads like a teammate wrote it: severity said in human words, counts said in a sentence, one short plain instruction per finding, no tool jargon like "placed inline" or "hot export". The machine format of the review artifact ([critical] markers that the gate and CI parse) does not change; only what humans read on GitHub does.

## Approach
Chosen: rewrite the rendering layer and the two auto-generated finding texts. reviewPayload maps critical, major, minor to "Must fix", "Worth fixing", "Minor" in inline comments and bullets, says the counts as a sentence, and says "Nothing to flag. Looks good." when the review is clean. The secret and impact auto-findings become one plain sentence each. The protocol's release row asks reviewer agents for one short plain sentence per finding, so the text unslopped quotes verbatim starts out human too.
Rejected: changing the artifact or parser format, because the gate, CI and countFindings depend on the [critical]/[major]/[minor] markers and machine format is the wrong place for voice. Rejected: rewriting reviewer-agent text on the way through, because paraphrasing someone else's finding can change its meaning.

## Out of scope
- Gate output wording in the terminal
- Tracker comments on issues
- The Impact section table in the PR body beyond the finding sentences
