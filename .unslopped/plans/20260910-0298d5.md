# Close the four journey gaps found by dogfooding: unguarded commits after a cycle, the quiz score shown before any attempt, log refusing without a cycle, and the stale README journey

Cycle: 20260910-0298d5
Started: 2026-09-10T00:12:35.662Z

## Goal
Close the four gaps a journey audit found by running two real cycles today.

1. An assistant can commit anything once a cycle completes. The commit guard is scoped to an active
   cycle, so the archive and debt commits at the end of both cycles today went through unguarded, and so
   would any source commit made at that moment.
2. The quiz gate reports a score before the human has answered anything.
3. `unslopped log` refuses to run without an active cycle, which is when its history is most wanted.
4. The README journey predates the ladder and the quiz, and its promise of five human moments is wrong.

## Approach
Rung 2 for three of the four, rung 7 for the guard. Every piece extends a check or a command that
already exists. Nothing new is introduced except one git helper.

- Gap 1, the guard. The obvious fix, dropping `active &&` in the commit branch, blocks every commit
  outside a cycle, including the chore commit the protocol tells the assistant to make before starting
  one. The narrower rule: with no cycle active, allow a commit only when every staged path sits under
  `.unslopped/`, and refuse it otherwise. Bookkeeping commits stay possible, source commits never
  happen without an approved message. Needs one git helper for the staged list, so rung 7, the minimum
  that works. The protocol line about the pre-cycle chore commit changes with it, because telling an
  assistant to do what the hook now refuses is incoherent.
- Gap 2, the quiz wording. Rung 2. quizCheck already branches on the record; add the attempts-zero case
  ahead of the score line.
- Gap 3, log. Rung 2. cmdLog already reads state; fall back to the archived cycles that metrics and
  recall already read, instead of refusing.
- Gap 4, the README. Rung 1 for most of it. The journey section exists and is right in shape, so amend
  the two steps that moved and the moment count rather than rewriting it.

Rejected:
- Dropping the active condition outright. Breaks the documented pre-cycle chore commit, and would have
  blocked real work on this repository three times today.
- Keeping a cycle active until its archive is committed. Touches the phase model and the completion path
  for a problem a staged-path check solves.
- Auto-committing the archive at completion. Removes the assistant's need for the hole without closing
  it, so an assistant could still hand-commit source after a cycle.

Revisable: whether the `.unslopped/` exemption should also require the paths to belong to the cycle that
just completed. Tighter, and it needs state the completion path does not keep yet.

## Handoff
What to verify: an assistant can no longer commit source code without an approved message, cycle or no
cycle.

How to reach it, in this repository:
1. With no cycle active, stage a source file and ask the assistant to commit it. The hook refuses,
   names the file, and points at `unslopped start`.
2. Stage only `.unslopped/DEBT.md` and ask again. It goes through, which is what the archive and debt
   commits at the end of every cycle need.
3. Start a cycle and try either one. Both refuse with the propose and approve instruction, unchanged.
4. Run `unslopped log` with no cycle active. It lists the archived cycles rather than erroring.
5. With the quiz enabled, record a quiz and run `unslopped check` at deploy before answering. It says
   the questions are waiting, not that you got zero right.

Rejections to try, with what should happen:
- A commit staging both bookkeeping and source: refused, and the message names the source file.
- `practices.messageApproval` set to false: commits are unguarded again, by configuration.
- `unslopped log` in a repository that never ran a cycle: prints `no cycles yet`, exits 0.

Gotchas:
- The guard reads the git index, so it sees what is staged at the moment of the commit. `git commit -a`
  stages after the hook has decided, which would have walked straight through the first version of this
  fix. It is covered: when the command carries `-a` or `--all`, the guard also reads the tracked
  modifications the commit would sweep in. `--amend` is deliberately not treated as `--all`.
- The pre-cycle chore commit is now the human's. The protocol text changed to say so, in both generated
  instruction files.

## Monitor
No gate failed on a first run, the second cycle in a row. Two real mistakes happened outside the gates,
which is where the remaining risk lives.

- Writing the handoff caught a bypass in the fix itself. `git commit -a` stages after the hook decides,
  so the first version of the guard would have waved it through, and no criterion would have noticed.
  The habit that caught it was writing down how a person would try to break the thing, not writing more
  tests. Worth doing before the release gate, not after.
- This cycle started on the previous cycle's branch instead of a fresh one, because `start` only refuses
  protected branches and `feat/leanness-ladder` was not protected. It turned out harmless only because
  that branch had already merged. Had it not, these commits would have landed inside someone else's open
  pull request, and the fix would have needed a force push, which is denied. `start` could warn when the
  current branch already has an open pull request.
- The classifier denied two shell commands this cycle: a `gh pr merge` and one heredoc that wrote files.
  Neither was worked around. The heredoc denial pushed plan and code edits onto the editing tools, which
  is also the fix for the escape corruption logged last cycle, so the constraint helped.
- Ticking twelve criteria took a second pass. Criterion nine claimed the README states the real number of
  human moments, and the first test only checked that the wrong number was gone. Counting the moments by
  hand gave six or seven, so the README and the test both changed before the tick was honest.

For next time: write the handoff before the release gate, since it is the step that finds bypasses, and
check what branch `start` is about to run on.
