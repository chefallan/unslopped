# Add the review workflow this project documents but never ran on its own pull requests

Cycle: 20260911-1c932e
Started: 2026-09-11T03:09:41.441Z

## Goal
The README says the engine reviews every pull request in CI with plain-language findings. This
repository has no `.github` directory at all, so none of the five pull requests merged today was
reviewed by it. The project documents a feature it does not run on itself.

## Approach
Rung 1, then rung 2. The workflow does not need to be written: `unslopped init --ci` already generates
it, and `ciWorkflow()` in src/init.ts is the source of truth for its contents. Running the command the
tool already ships is the whole change. Nothing is authored here except the changelog note.

The workflow calls `npx -y unslopped review --pr=<number>`, which resolves the latest published version
at run time. npm is on 0.1.3 today, so until 0.1.8 publishes, CI reviews with the older scanner and
picks up the leanness pass on its own afterwards. That is why this does not have to wait for the
publish: no version is pinned, and it corrects itself.

With `practices.reviewCommand` unset, CI posts only the findings unslopped generates itself: leaked
credentials, exploitable-looking lines, over-engineered lines, and changed hot exports with no test.
That is real coverage without an API key or a secret in the repository, and the generated file carries a
commented example for anyone who later wants a model-backed reviewer.

Rejected:
- Writing the workflow by hand. Rung 1. It would drift from `ciWorkflow()`, and the generator is tested.
- Waiting until after the publish. Nothing is pinned, so the ordering does not matter.
- Adding a reviewCommand and a model API key in the same change. That is a secret and a cost decision,
  and it belongs to the human, not to a cycle that is meant to close a documentation gap.

## Out of scope
- Publishing 0.1.8. Irreversible, needs npm credentials this shell does not have, and it is the human's.
- Configuring a model-backed reviewer.
- Enabling the quiz here, still waiting on a human to answer one.

## Preferences
- PR review comments use plain language: short sentences, no jargon, severity said in human words  (global)
- Every command the tool asks a human to run must arrive with its context: what was verified, what it unlocks, how to decline  (global)

## Handoff
What to verify: this project now reviews its own pull requests.

How to reach it:
1. Open any pull request against main. The Unslopped review action runs on it.
2. Read the checks tab. The job posts inline findings and a summary comment, or says there is nothing
   to flag.

Rejections to try, with what should happen:
- A pull request carrying a credential-shaped string: flagged as critical, and the check fails.
- A pull request adding `JSON.parse(JSON.stringify(x))`: flagged as minor once 0.1.8 is on npm. Before
  that, CI runs 0.1.3 and will not see it, because the workflow resolves the latest published version
  rather than pinning one.

Gotchas:
- `practices.reviewCommand` is unset, so CI posts only what unslopped finds by itself. No API key is
  needed and none is in the repository. The generated file has a commented example for adding one.
- `unslopped init --ci` with no `--only` also writes instruction files for cursor, copilot, windsurf and
  gemini, which this repository has never tracked. Those were removed; only the two `.github` files
  were kept.
- The workflow is not in the published package. `files` ships bin, dist, README and LICENSE only.
