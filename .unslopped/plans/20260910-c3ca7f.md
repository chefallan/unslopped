# Absorb ponytail's review and audit: flag over-engineered lines in the diff and across the repo

Cycle: 20260910-c3ca7f
Started: 2026-09-10T07:34:09.840Z

## Goal
Absorb the half of ponytail we skipped. The ladder tells the assistant how to decide; nothing checks
the result. `ponytail-review` reads a diff and returns what to delete, `ponytail-audit` does the same
across a repository. Neither has an equivalent here, so a plan can name rung 7 over work rung 3 would
have solved and no gate contradicts it.

## Approach
Rung 2. `scanExploitable` in src/vulns.ts is already a line-based pattern scanner whose findings
`unslopped review` folds into the artifact. Copy that shape for leanness, one file, same cap, same skip
list, same automatic fold. No new subsystem, no new command for the diff pass.

What a line-based scanner can honestly enforce is rungs 3 and 6: the standard library already does it,
or it fits on one line. Rungs 1, 2, 4 and 5 need to know what the rest of the codebase and its
dependencies already provide, which is the assistant's job with the code map, not a regex's. The plan
says so rather than implying the scanner covers the whole ladder.

Findings are minor, not major. Bloat should be visible in every review without shutting the release
gate, which only critical findings do. A deletion list that blocks a release would get switched off.

The repository pass reuses the same patterns behind `unslopped review --repo`, printing findings without
recording an artifact, because a repo-wide sweep is not a review of this cycle's work.

Rejected:
- A new top-level command for the audit. Rung 1. `review` already owns findings, and `practices.audit`
  already means the dependency audit, so a second `audit` would read as that.
- Parsing the code into a tree to catch wrappers and single-implementation interfaces. That is the
  honest way to enforce rungs 1 and 2, and it is a parser plus the graph, not a cycle.
- Flagging on style guesses such as `typeof x === 'undefined'` or `return await`. Both are defensible in
  real code, and a scanner that cries wolf gets disabled, which costs more than it catches.

Revisable: the pattern list and the cap. Adding a pattern later is one line plus one test.

Found by running the scanner on this repository before shipping it, which is the only way this was going
to surface. Five hits, three of them false. Two filter patterns matched straight past the closing paren,
so `filter(...).map((f) => f.split('/')[0])` read as `filter(...)[0]`; both now stop at the paren. The
boolean pattern flagged `flags.pr === true`, where the value is a string-or-boolean union and the
comparison carries real meaning, so it now fires only when the whole condition is that comparison. The
forEach-into-push pattern is gone: appending to an accumulator is ordinary code, and the rewrite belongs
to neither rung 3 nor rung 6, which is the scope this scanner claims. Its test is inverted rather than
deleted, so the decision is recorded and a future pattern cannot quietly reintroduce the noise.

## Handoff
What to verify: the review now argues back when a diff reaches for the long way round.

How to reach it:
1. Add a line such as `const copy = JSON.parse(JSON.stringify(input));` to a source file in a cycle.
2. Run `unslopped review --file=<anything.md>`. The output says how many over-engineered lines were
   added as findings, and the artifact carries them as `[minor]` with the file, the line and what to
   write instead.
3. Run `unslopped review --repo` anywhere. It reads every tracked source file and prints the same kind
   of finding, or says the repository looks lean. It records nothing.

Rejections to try, with what should happen:
- The same line in a test file, a lockfile, a minified file or markdown: not flagged.
- `structuredClone(input)`, `rows.some(...)`, `{ ...base, ...extra }`: not flagged.
- `keys.filter((f) => f.includes('/')).map((f) => f.split('/')[0])`: not flagged. The filter patterns
  stop at the closing paren, which is the bug found by running this on our own code.
- `if (prNumber !== null || flags.pr === true)`: not flagged. The boolean pattern fires only when the
  whole condition is the comparison, because a union-typed value compared to `true` means something.
- `practices.bloatScan` set to false: the review artifact holds only what the reviewer wrote.

Gotchas:
- The findings are minor, so they never block a release. That is deliberate. A deletion list that shut
  the gate would be switched off within a week.
- Version 0.1.7, not 0.1.6, because PR #3 already claims 0.1.6. Both insert their entry directly under
  the `# Changelog` heading, so whichever merges second has one conflict hunk to resolve there and in
  package.json.
- The scanner reads one line at a time, so anything spanning lines is invisible to it. Wrappers,
  single-implementation interfaces and dead config knobs need the parser this cycle rejected.
