# Approvals name what they approve

Cycle: 20260902-a4cc55

## Goal
The permission dialog shows only the command line, so the command line carries the decision. Commit and pr approvals take a subject flag that must match the proposal's first line, deploy approvals take a for flag that must name the active cycle, and mismatches refuse without recording anything. The protocol tells hooked assistants to always request approvals this way, so the human reads the title inside the dialog instead of approving blind.

## Approach
Chosen: optional verified flags on approve. `--subject "<title>"` on commit and pr compares against the proposal's first line; `--for "<cycle id and goal>"` on deploy must start with the active cycle id. A mismatch fails with the real value shown, so a stale or fabricated request cannot ride a reflex click. Bare approve stays valid for humans typing after reading `unslopped proposals`. The protocol's request rule gains the exact shapes to use.
Rejected: making the flags mandatory, because typed-mode humans read the text first by definition and forcing flags punishes them. Rejected: relying on the hook's reason field, because the dialog demonstrably does not render it.
