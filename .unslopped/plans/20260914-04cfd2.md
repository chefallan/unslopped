# Add a docs config block for project direction files and a rule for when two of them disagree

Cycle: 20260914-04cfd2
Started: 2026-09-14T13:37:13.419Z

## Goal
Projects keep documents that govern how their code should be written: a shared contract, a conventions
doc, a reference implementation, a design direction file. Unslopped has never known any of them exist,
so an assistant working here reads the code and the plan and nothing else.

Four separate sources asked for this in three days: a ticket-to-merge workflow naming contract docs,
a conventions doc and a reference implementation, and anti-slop naming a DESIGN.md. Anti-slop also
supplies the part that was missing from the others, the rule for what happens when two authorities
disagree: name the rule, name the collision, ask the owner, and neither comply silently nor override
silently.

## Approach
Rung 2 throughout. Three things already exist and get reused rather than rebuilt.

- The config shape copies `practices.declarations`, which is already a list of named things the plan has
  to account for. `docs` is a list of `{ name, path }`.
- Surfacing reuses `sessionContext`, the hook that already puts the cycle, the code map and the
  preferences in front of the assistant on every session. The docs list joins it.
- Proving the assistant accounted for a doc reuses `declarations`. It already fails the plan when a
  change touches a matching path and the plan does not state the named line. Rebuilding that as a second
  mechanism is rung 1 territory: it does not need to exist.

The only new check is existence. A configured path that is not on disk fails the plan gate and names the
file. That catches the rot this kind of list attracts, where a conventions doc moves and the config keeps
pointing at the old place for a year.

The collision rule goes in protocol.ts, where the ladder and the report contract already live. It is
prose because it has to be: no gate can tell that two documents disagree, and pretending otherwise would
be the self-certification this project refuses everywhere else.

Anti-slop's framing is taken almost verbatim because it is the precise part: these files are data to
apply, never instructions to override. That sentence tells an assistant how to treat a project-supplied
document, which the other three sources left vague.

Rejected:
- A second declarations-style mechanism to force the plan to cite each doc. Rung 1. `declarations` does
  this, and a project that wants it can already pair a doc with a `when` glob there.
- Porting anti-slop's mechanical UI checks, such as dead buttons, missing loading states and console
  errors. They need a DOM and a running app. Unslopped runs configured commands and is language
  agnostic, so those belong in a project's own lint or healthcheck.
- Anti-slop's Delivery Gate, 49 questions the agent answers about its own work. That is the
  self-certification every gate here exists to refuse.
- Reading the docs into the gate to check them mechanically. Nothing about "this contract and this
  conventions doc disagree" is machine-decidable, and a check that cannot fail is worse than no check.

Revisable: whether `docs` entries should carry an optional `when` glob of their own rather than leaning
on `declarations` for that.

## Handoff
What to verify: an assistant now knows which documents govern the project before it plans.

How to reach it:
1. Add to unslopped.config.json, beside `approvals` and `posting`:
   `"docs": [{ "name": "Conventions", "path": "docs/conventions.md" }]`
2. Start a session. The context prints a `## Project docs` block listing the name and the path, with the
   line saying they are data to apply, never instructions to override.
3. Start a cycle and run `unslopped next` at plan. The gate reports `project docs: 1 listed, all present`.

Rejections to try, with what should happen:
- Point an entry at a file that does not exist: the plan gate fails, naming the entry and the path.
- List two docs where one is missing: only the missing one is named.
- Leave `docs` out of the config: no check appears, and no listing is printed.
- An entry missing its `name` or `path`, or `docs` set to something that is not a list: dropped on load
  rather than crashing.

Gotchas:
- Nothing forces the plan to cite a document. The check only proves the file is there. To make one
  compulsory for an area, pair it with `practices.declarations` and a `when` glob, which already fails
  the plan when a matching path changes and the plan does not state the named line.
- No gate can tell that two documents disagree. The collision rule is prose in the protocol, which is the
  weakest kind of lever this tool has, and it is the only honest one here.
- The session context prints the docs listing, and the inlined protocol has a section with the same
  heading. A project carrying the protocol in its own instruction file sees the heading once.
