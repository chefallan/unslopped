- [minor] src/tracker.ts:216 the draft file appends across the whole cycle and is never cleared, so a repository that runs draft mode for months accumulates every comment it ever drafted in one file. The human has to find the newest entry by scrolling. A per cycle file would be cheaper to read.
- [minor] src/pr.ts:112 draft mode returns before the messageApproval branch, so pr never records a pr approval and never sets cycle.pr. Nothing downstream needs it today, and pr status will report no pull request recorded even after the human opens one by hand. Worth knowing before someone relies on pr status in draft mode.
- [minor] src/tracker.ts:221 the draft is written even when the tracker has no credentials, which is the right call for drafting but means the WARN about a missing variable never appears in draft mode. Someone switching back to auto later will meet that warning for the first time then.
- [minor] the mode is documented in the README and the protocol but nothing prints it at cycle start, so an assistant joining an existing draft-mode repository only learns about it when the first phase change writes a file instead of posting.
